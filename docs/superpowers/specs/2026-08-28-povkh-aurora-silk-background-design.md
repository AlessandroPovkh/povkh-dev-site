# Povkh.Dev Aurora Silk background design

Дата: 2026-08-28
Статус: approved
Поверхность: существующие русские страницы Povkh.Dev

## 1. Решение

Заменить визуально плоский чёрный фон русской поверхности единым динамическим фоном Aurora Silk. Фон должен создавать спокойную глубину и мягкий цветовой перелив, не становясь самостоятельным визуальным аттракционом и не конкурируя с типографикой, кейсами или интерактивным знаком.

Выбранный характер: глубокая сливово-графитовая основа с двумя крупными мягкими полями — приглушённым розовым и холодным фиолетовым. Поля медленно перемещаются и слегка меняют масштаб. Вращение, cursor parallax, яркий glow, частицы, сетка и gaming-эффекты исключены.

## 2. Архитектура

Добавить один декоративный компонент `AmbientBackdrop.astro`, который `BaseLayout.astro` выводит только для `locale === "ru"`. Компонент располагается первым визуальным слоем внутри `body`, не участвует в document flow, не перехватывает события и скрыт от accessibility tree через `aria-hidden="true"`.

Компонент содержит три CSS-слоя:

1. Base veil — фиксированная сливово-графитовая заливка вместо чистого `#08080a`.
2. Rose field — крупный мягкий radial-gradient в верхней правой и центральной области.
3. Violet field — более холодный radial-gradient в нижней левой области.

Слои используют только `transform` и `opacity`. Canvas, WebGL, SVG filters, runtime JavaScript и новые зависимости не применяются.

## 3. Движение

- Rose field: цикл 18 секунд, `ease-in-out`, `alternate`, смещение не более 6% ширины/высоты и масштаб до 1.08.
- Violet field: цикл 24 секунды с отличающейся фазой, смещение не более 5% и масштаб до 1.1.
- Никакого полного вращения или резкого изменения направления.
- Анимация непрерывная, но визуально медленная: пользователь не должен считывать конкретный повтор цикла во время обычного просмотра страницы.
- При `prefers-reduced-motion: reduce` обе анимации отключаются; остаётся статическая композиция с теми же цветами и контрастом.

## 4. Интеграция с существующей системой

Главная и внутренние RU-страницы используют один фон, чтобы поверхность воспринималась цельной. Существующий `.ambient-field` главной перестаёт владеть глобальной атмосферой и не дублирует новый компонент.

Основной content layer, header, footer и секции располагаются выше backdrop. Непрозрачные большие поверхности, которые полностью скрывают перелив без смысловой причины, переводятся на тёмные полупрозрачные значения. Текстовые reading zones сохраняют достаточную плотность заливки; цветовой перелив не проходит ярким пятном непосредственно под длинными абзацами.

Карточки problem, result, формы и case surfaces остаются отдельными рабочими поверхностями. Их прозрачность допускает только слабое проявление фона и не должна создавать glassmorphism как основной стиль.

## 5. Цвет и интенсивность

- Base: диапазон `#10090f` — `#0a090c`.
- Rose field: оттенки семейства `#ca1b71` с эффективной непрозрачностью не выше 0.28.
- Violet field: оттенки семейства `#6f3ba7` с эффективной непрозрачностью не выше 0.22.
- Акцентный розовый `#ff2f92` остаётся цветом действий и signal-точек; фон не должен визуально конкурировать с ним по яркости.
- На мобильных экранах эффективная opacity фоновых полей уменьшается на 20%: rose не выше 0.224, violet не выше 0.176.

## 6. Accessibility и производительность

- Backdrop получает `pointer-events: none`, `aria-hidden="true"` и не создаёт focusable nodes.
- Текстовый контраст проверяется в реальном браузере на hero, карточках, формах и legal reading pages.
- Анимируются только compositable-свойства `transform` и `opacity`; layout-свойства не анимируются.
- Одновременно работают не более двух движущихся цветовых полей.
- На `prefers-reduced-motion: reduce` computed animation должен быть `none`.
- Фон не должен увеличивать `scrollWidth`, создавать горизонтальный скролл или менять геометрию документа.

## 7. Responsive behavior

- Desktop: оба цветовых поля видимы, но между поверхностями заметнее, чем под текстом.
- Tablet: поля сохраняют desktop-пропорции относительно viewport; движение остаётся тем же.
- Mobile: каждое поле имеет ширину не меньше 140vw, чтобы не возникали резкие цветовые границы; интенсивность уменьшается на 20%, движение сохраняется только при standard motion preference.
- Компонент покрывает viewport через fixed positioning и продолжает композицию при прокрутке без визуальных швов между секциями.

## 8. Error и fallback behavior

- При отсутствии поддержки CSS animation отображается статический gradient fallback.
- При отсутствии поддержки современных color-функций используются обычные RGB/hex значения.
- JavaScript не требуется, поэтому ошибка клиентского runtime не отключает фон и не влияет на содержимое.
- Если backdrop не загрузится или будет скрыт, страницы остаются читаемыми на базовой сливово-графитовой заливке.

## 9. Проверки

1. Component contract: backdrop рендерится на всех RU routes и отсутствует на EN/IT.
2. Motion contract: два движущихся слоя при standard motion; animation отсутствует при reduced motion.
3. Geometry contract: `scrollWidth === clientWidth` на representative desktop/mobile routes.
4. Contrast review: homepage hero, problem/result rows, services, work, contact и legal page.
5. Visual evidence: desktop и mobile screenshots минимум главной, services, work и contact.
6. Regression: content contract, Astro check, build и текущие RU browser tests.

## 10. Acceptance criteria

- Ни одна RU-страница больше не воспринимается как расположенная на чистом чёрном фоне.
- Перелив заметен в первом экране и между крупными секциями, но не мешает читать текст.
- Фон выглядит непрерывным при прокрутке и одинаково принадлежит главной и внутренним страницам.
- Акцентные кнопки и signal-элементы остаются визуально сильнее фоновых розовых областей.
- Reduced-motion версия полностью статична.
- На мобильных и desktop отсутствует новый overflow и layout shift.
- Публичные тексты, кейсы, маршруты и case assets не изменены.

## 11. Scope boundary

В deliverable входят только shared RU backdrop, необходимые изменения прозрачности существующих RU surfaces, motion/reduced-motion behavior, проверки и screenshots. Не входят новые тексты, новая IA, изменение кейсов, EN/IT sync, зависимости, commit, push, merge или deploy.
